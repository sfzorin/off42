# OFF42 for iPad and iPhone

A native SwiftUI app for iPadOS and iOS (ARCHITECTURE.md, decision D11) over the shared Rust engine, called through
the UniFFI crate [`rust/crates/off42-mobile`](../rust/crates/off42-mobile) — the same crate and calls as the Android
app and the web app. Bundle id **`cc.off42.office`** (the same id as on Android; the Mac App Store variants use
`cc.off42.<app>`, see [appstore/README.md](../appstore/README.md)), name **OFF42**, iOS/iPadOS 17 or later, universal
(iPad and iPhone).

It is offline: the app makes no network connections, asks for no permission, keeps no preferences, has no account,
analytics or tracking. Its privacy manifest declares no collected data and one required-reason category (file
timestamp APIs, referenced by the engine's Rust standard library; see appstore/ios/README.md). Files are read only when the user opens them (document picker, "Open in"/Share from another
app) and written only where the user saves them (system save dialog) or hands them to another app (Share).

## Screens

Six sections, as on Android. On iPad a three-column `NavigationSplitView`: sections | open files (or a section's
generators) | the open file. On iPhone the same split view collapses into a stack: sections → files → file. iPhone
Pro Max in landscape shows the three columns too.

| Section | What it does |
| --- | --- |
| Documents | DOCX, ODT, RTF, Markdown, HTML and TXT: the engine's HTML as a white page on a grey canvas in a `WKWebView` with JavaScript off, a non-persistent data store, every navigation but the initial page cancelled and a Content-Security-Policy that allows no network, frame or script (only inline styles and `data:` images/fonts); word, character and paragraph counts; **Save as** DOCX/ODT/RTF/MD/HTML/TXT. When a conversion would drop opaque Word/OpenDocument package parts, the app asks first. |
| Spreadsheets | XLSX, ODS, CSV and XLS (read-only): grid with lazy rows and pinned column letters, numbers right-aligned, sheet tabs along the bottom, first 1000 rows × 100 columns. Save as XLSX/ODS/CSV; "Sheet values as CSV" (the only export for XLS). |
| Presentations | PPTX and ODP as the engine reads them: each slide's title, bullets, tables and picture placeholders on a white 16:9 slide, a slide strip (left on iPad, bottom on iPhone), speaker notes under the slide, hidden slides dimmed. Save as PPTX/ODP. |
| PDF | Pages rendered by PDFKit (`PDFView`, continuous, with a page indicator); the engine's page count, metadata, bookmarks, attachments and form fields in an info sheet; save a copy, share. Password-protected PDFs show a notice. |
| Labels & codes | Codes: QR, Data Matrix, Code 128, Aztec with a live preview; save PNG or SVG, share. Label sheets: A4 sheets from `text \| code \| copies` lines on a built-in stock (searchable) or a custom size, with a preview of the first page; save or share the PDF. Product marks: the 97 marks with search, category filter and a detail sheet (purpose, warnings, licence notes); save SVG or PNG at any width. |
| Signatures & stamps | Six signature variants per name, form, pen and ink, each with "New impression", save and share as transparent PNG. Stamps from the built-in templates with editable fields (dates default to today), ink, live preview, new impression, save or share at 2× scale. |

Engine calls are synchronous; the app runs them in detached tasks (`Engine.run`) and keeps the UI on the main actor.
Open files live in memory in `AppModel` for the session, so rotation, size-class changes and dark mode keep them.
A file received through "Open in" is copied by iOS into `Documents/Inbox`; the app reads it and deletes that copy
(`LSSupportsOpeningDocumentsInPlace` is off). ShareLink writes the shared bytes to the app's temporary folder only
when a destination asks for them.

Style: native iOS idioms (inset grouped lists, toolbar menus, sheets, searchable lists), the accent colours of the
approved redesign per section (documents `#2f6fde`, spreadsheets `#1e8e4f`, presentations `#e0891b`, PDF `#d23f31`,
labels `#0b8a8a`, signatures `#7b4fc4`), light and dark mode from the system, Dynamic Type for all UI text (slides are
drawn at the slide's own scale), VoiceOver labels (grid cells read their address and value, slides their number and
title, images their content). The app icon is the site's "42" mark (`scripts/make-icon.py`).

### Languages

The 20 languages of the site and the web app, Arabic right to left. [`OFF42/Localizable.xcstrings`](OFF42/Localizable.xcstrings)
is generated by [`scripts/generate-strings.py`](scripts/generate-strings.py) from the web app's `web/src/locales/*.json`
(through the key table of the Android generator, `android/scripts/generate-strings.py`), the Android-only strings
(`android/scripts/strings-android.json`) and the iOS wording in [`scripts/strings-ios.json`](scripts/strings-ios.json);
rerun it after changing any of them (CI fails when the catalog is out of date). As on Android and the web, engine
messages are in English, and stamp template titles exist in English, Russian and Turkish only.

### Limits

What the engine does not do on any platform yet is missing here too: editing, exporting documents/sheets/slides to
PDF, slide pictures and layouts, PDF annotation and OCR. A drawn signature is an image, not a certificate-based
digital signature. Large files are read into memory. There is no share extension: OFF42 appears in the share sheet's
app row and in "Open in" through its document types. Printing is not offered.

## Build

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from [`project.yml`](project.yml);
`*.xcodeproj` is not committed. Requirements: Xcode 16 or later with the iOS SDK, `brew install xcodegen`, the Rust
toolchain with `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`.

```sh
sh rust/scripts/build-mobile-apple.sh     # rust/build/apple: Off42MobileFFI.xcframework, swift/Off42Mobile.swift
cd ios && xcodegen generate               # OFF42.xcodeproj (targets OFF42, OFF42Tests, OFF42UITests)
xcodebuild -project OFF42.xcodeproj -scheme OFF42 -destination 'platform=iOS Simulator,name=iPhone 16 Pro Max' test
```

The app target compiles the generated `Off42Mobile.swift` and links the static engine library from the XCFramework
(`liboff42_mobile.a`, profile `mobile-release`: LTO, stripped). `ExportOptions.plist` is the template for App Store
exports. Strings, listing texts and the icon are regenerated with `python3 ios/scripts/generate-strings.py`,
`python3 appstore/ios/make_listings.py` and `python3 ios/scripts/make-icon.py` (Pillow).

For this project the tests and builds run only in GitHub Actions (the owner's Mac is not used for simulators or GUI
builds).

## Tests

- `cargo test -p off42-mobile` (Android workflow): the bindings against the cores.
- `OFF42Tests` (XCTest, hosted in the app, real engine): every fixture of
  [`android/app/src/androidTest/assets/fixtures`](../android/app/src/androidTest/assets/fixtures) opens in its
  viewer's content (document HTML text, spreadsheet A1, slide titles, PDF pages, with PDFKit's page count equal to the
  engine's); conversions MD→DOCX, DOCX→ODT (package-parts error, then with consent), CSV→ODS, PPTX→ODP, XLS values →
  CSV; the model's Save as flow including the question and the bytes handed to the save dialog; file names and types;
  grid helpers; the page's Content-Security-Policy; codes, label sheets, marks, signatures (deterministic per seed)
  and stamps; language codes; and the compiled String Catalog: all keys in all 20 languages with the same format
  arguments as English.
- `OFF42UITests` (XCUITest, iPhone and iPad simulators): opens every fixture format in its viewer and checks what is
  shown (web page text, cell values, slides, PDF pages and info); converts MD→DOCX, DOCX→ODT (answering the
  package-parts alert), CSV→ODS, PPTX→ODP and XLS→CSV values through the toolbar Save as menu and checks the written
  files with the engine; generates and saves a QR code, a label sheet, a product mark, a signature and a stamp and
  checks the PNG/PDF bytes; rotates with a file open; switches the system to dark mode with a file open and checks the
  screen pixels; launches in Arabic and checks the right-to-left layout; and checks that the real document picker and
  save dialog appear. Files are opened through the same `AppModel.open(url:)` as "Open in" (launch environment
  `OFF42_UITEST_OPEN`); the system save dialog is replaced by writing into a test folder (`OFF42_UITEST_EXPORT_DIR`),
  except in the picker test.

## CI

[`.github/workflows/ios.yml`](../.github/workflows/ios.yml), on `macos-latest`:

1. **engine**: String Catalog and App Store listing checks, `build-mobile-apple.sh` (device and simulator libraries,
   Swift bindings, XCFramework), type-check of the bindings.
2. **build**: XcodeGen, a Release archive for devices, [`scripts/check-app-bundle.sh`](scripts/check-app-bundle.sh)
   (privacy manifest, document types, every required-reason C API the binary references declared in the manifest, no
   networking API), the IPA as
   artifact `off42-ios-ipa` and sizes in the job summary. Unsigned unless the signing secrets below exist.
3. **test** (iPhone and iPad): a fresh simulator of the newest 6.9-inch iPhone ("Pro Max") and 13-inch iPad Pro with
   the newest iOS runtime ([`scripts/create-simulator.py`](scripts/create-simulator.py)), status bar at 9:41, unit
   and UI tests. The App Store screenshots are artifacts `ios-screenshots-iphone-6.9` and `ios-screenshots-ipad-13`
   (`iphone-*.png` portrait, `ipad-*.png` landscape; 1–7 light, 8 dark, 9 Arabic); the result bundle is kept on
   failure.

## Signing and release

CI builds unsigned without secrets. With these repository secrets it signs the archive and exports an App Store IPA
(`ExportOptions.plist`: method `app-store-connect`, manual signing, the profile for `cc.off42.office`):

| Secret | Content |
| --- | --- |
| `IOS_TEAM_ID` | The Apple Developer Team ID |
| `IOS_DISTRIBUTION_CERTIFICATE_P12_BASE64` | base64 of the "Apple Distribution" certificate with its private key (.p12) |
| `IOS_DISTRIBUTION_CERTIFICATE_PASSWORD` | the .p12 password |
| `IOS_APP_STORE_PROFILE_BASE64` | base64 of the App Store provisioning profile for `cc.off42.office` |
| `APP_STORE_CONNECT_API_KEY_ID`, `APP_STORE_CONNECT_API_ISSUER_ID`, `APP_STORE_CONNECT_API_KEY_BASE64` | an App Store Connect API key (base64 of the .p8); used only when the workflow is started by hand with "upload" |

The build number is the workflow run number. The signed path has not run yet (no account); the listing, privacy
answers and the owner's steps are in [appstore/ios/README.md](../appstore/ios/README.md).
