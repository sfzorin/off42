# Mac App Store and notarized DMG

Decision D12 (ARCHITECTURE.md): the six Mac apps are also published on the Mac App Store as a sandboxed build
variant of the same Swift sources. The DMG stays, signed with Developer ID and notarized.

| What | Where |
| --- | --- |
| Sandboxed variant | Swift compile condition `APP_STORE`, built by `scripts/build-app-store.sh` into `build/app-store` (Swift build folder `.build/app-store`) |
| Variant-only code | `Sources/Kit42/AppStoreEdition.swift` (whole file under `#if APP_STORE`) and small `#if APP_STORE` blocks at the call sites |
| Entitlements | `Resources/<App>/AppStore.entitlements`, `Resources/QuickLook/AppStore.entitlements` |
| Privacy manifests | `Resources/<App>/PrivacyInfo.xcprivacy` (copied into `Contents/Resources` of the App Store bundles only) |
| DMG signing, notarization | `scripts/sign_and_notarize.sh`, `Resources/DeveloperID/*.entitlements` |
| Listing drafts | `appstore/mac/listings/<language>.json`, generated by `appstore/mac/make_listings.py` |

`./build.sh` without `SUITE42_APP_STORE=1` runs the same commands as before and compiles none of the variant's code.

## Identifiers

Proposed bundle ids (separate from the DMG's `com.sfzorin.*`, so both versions can be installed side by side and
keep their own settings): `cc.off42.pdf42`, `cc.off42.doc42`, `cc.off42.xls42`, `cc.off42.img42`, `cc.off42.ppt42`,
`cc.off42.scn42`, and for the Quick Look extensions `cc.off42.doc42.preview`, `cc.off42.doc42.thumbnail`,
`cc.off42.xls42.preview`, `cc.off42.xls42.thumbnail`. They must equal the ids registered in the account;
`APP_STORE_BUNDLE_PREFIX` changes the prefix.

App Group: `<TEAMID>.cc.off42` (macOS style, prefixed with the Team ID). The build script writes it into the
entitlements and into Info.plist (`Suite42AppGroup`), where the code reads it.

## Export compliance (encryption)

The App Store Info.plist sets `ITSAppUsesNonExemptEncryption` to `false`. Reasoning, from the code:

- TLS for timestamps, revocation and CSC goes through `URLSession` (Apple's operating system).
- PDF password protection uses PDFKit's own encryption (`PDFDocumentWriteOption.userPasswordOption`).
- Signatures (PAdES, XAdES, CMS) use Security.framework / CryptoKit keys; signing and hashing serve authentication
  and integrity, not confidentiality. The code has no cipher of its own (only SHA-1/SHA-256 hashes through CryptoKit).
- CryptoPro (GOST) is not used in this variant.

This is a technical summary, not legal advice. **Owner:** confirm it when App Store Connect asks the encryption
questions (uses encryption → only Apple's operating-system encryption / exempt). If the answers differ, remove the key
from `scripts/build-app-store.sh` and answer per build, or provide the export documentation (for example the French
declaration) App Store Connect asks for.

## Privacy

- Privacy Policy URL: `https://off42.cc/en/privacy/` (localized at `/<lang>/privacy/`); Support URL:
  `https://off42.cc/en/support/`; contact: tr.zorin@gmail.com.
- App Privacy ("nutrition label"): **Data Not Collected**. The only network features are PDF42's timestamps from the
  chosen TSA (DigiCert by default), revocation data from the addresses in certificates, and CSC remote signing, which
  sends only a hash to the user's provider; nothing reaches the developer.
- Privacy manifests: no tracking, no collected data; required-reason APIs found in the code —
  UserDefaults `CA92.1` (own) and `1C8F.1` (App Group suite), file timestamps `C617.1` (stamp library in the App
  Group), `3B52.1` (documents the user opened), `DDA9.1` (dates shown in IMG42's Info panel and PDF42's lists),
  system boot time `35F9.1` (IMG42: `systemUptime` paces Live Text). No disk-space or keyboard APIs.

## Owner's steps

### 1. Apple Developer account (developer.apple.com)

1. Note the Team ID (Membership details).
2. Certificates, Identifiers & Profiles → Identifiers → App IDs: register the ten bundle ids above (explicit, macOS).
   For the six apps enable **App Groups**; leave other capabilities off.
3. Identifiers → App Groups: register `<TEAMID>.cc.off42` (on macOS the Team ID prefix is the usual form) and assign
   it to the six app ids.
4. Certificates: create **Mac App Distribution** ("3rd Party Mac Developer Application" / "Apple Distribution"),
   **Mac Installer Distribution** ("3rd Party Mac Developer Installer") and **Developer ID Application** (for the
   DMG). Install them in the login Keychain (`security find-identity -v` lists them).
5. Profiles: create a **Mac App Store** distribution profile for each of the ten ids. Save them as
   `PDF42.provisionprofile`, …, `DOC42.preview.provisionprofile`, `DOC42.thumbnail.provisionprofile`,
   `XLS42.preview.provisionprofile`, `XLS42.thumbnail.provisionprofile` in one folder.
6. Notarization credentials for the DMG:
   `xcrun notarytool store-credentials suite42 --apple-id <apple id> --team-id <TEAMID>` (app-specific password), or
   with an App Store Connect API key (`--key`, `--key-id`, `--issuer`).

### 2. App Store Connect (appstoreconnect.apple.com)

1. Agreements, Tax and Banking: accept the Paid Apps agreement only if needed (free apps need just the standard one).
2. Apps → New App, six times: platform macOS, name (see listings; names are unique store-wide — if "PDF42" is taken,
   use e.g. "PDF42 by OFF42"), primary language English (U.S.), the bundle id, SKU (e.g. `off42-pdf42`).
3. App Information: category Productivity (IMG42 may use Graphics & Design), content rights, age rating
   questionnaire (no objectionable content). Privacy Policy URL and App Privacy → "Data Not Collected".
4. Pricing: Free. Availability: as wanted.
5. Version page per language: paste name, subtitle, promotional text, description, keywords from
   `appstore/mac/listings/<language>.json` (`appStoreLocale` says which App Store localization it is; Filipino has
   none). Support URL and marketing URL are in the same file. Screenshots: 1280×800 to 2880×1800, 16:10.
6. App Review information: a contact, and notes such as "No account needed. Smart cards with third-party PKCS#11
   modules and CryptoPro are not available in this version; signing uses Keychain certificates."
7. Keys (Users and Access → Integrations): create an App Store Connect API key for uploads; put the `.p8` in
   `~/.appstoreconnect/private_keys/`.

### 3. Build, validate, upload

```bash
# Local check without any certificate (ad-hoc signed, sandboxed): build/app-store/*.app and unsigned *.pkg
scripts/build-app-store.sh

# Store build
APP_STORE_TEAM_ID=<TEAMID> \
APP_STORE_IDENTITY="3rd Party Mac Developer Application: <Name> (<TEAMID>)" \
APP_STORE_INSTALLER_IDENTITY="3rd Party Mac Developer Installer: <Name> (<TEAMID>)" \
APP_STORE_PROFILES=~/off42-profiles APP_STORE_BUILD_NUMBER=1 \
APP_STORE_VALIDATE=1 APP_STORE_API_KEY=<key id> APP_STORE_API_ISSUER=<issuer id> \
scripts/build-app-store.sh
# then the same with APP_STORE_UPLOAD=1 (or upload build/app-store/*.pkg with Transporter)

# Checks of a built bundle
codesign -d --entitlements :- build/app-store/PDF42.app
codesign --verify --strict --verbose=2 build/app-store/PDF42.app
build/app-store/PDF42.app/Contents/MacOS/PDF42 --selftest

# Notarized DMG (Developer ID)
DEVELOPER_ID="Developer ID Application: <Name> (<TEAMID>)" NOTARY_PROFILE=suite42 VERSION=1.0.0-preview.3 \
scripts/sign_and_notarize.sh
```

`xcrun altool` (validate/upload) comes with Xcode only, so Xcode's license must be accepted once
(`sudo xcodebuild -license accept`). The builds, `codesign`, `productbuild`, `notarytool` and `stapler` also work
with the Command Line Tools (`DEVELOPER_DIR=/Library/Developer/CommandLineTools`), which is how the checks below
were run while the Xcode license was not accepted.

Every upload needs a higher `APP_STORE_BUILD_NUMBER`. After the first upload, test with TestFlight for macOS
before submitting for review.

## Checked so far (2026-11-26, macOS 27.0, Swift 6.3.1 from the Command Line Tools)

- `scripts/build-app-store.sh` without identities: six ad-hoc signed, sandboxed bundles and unsigned .pkg files;
  `codesign -d --entitlements :-` shows the entitlements above; bundle ids, `Suite42AppGroup`,
  `ITSAppUsesNonExemptEncryption`, `PrivacyInfo.xcprivacy` present; no `Contents/Helpers`.
- `--selftest` of the sandboxed bundles' PDF42, XLS42, IMG42, PPT42 and SCN42 (headless, inside the sandbox):
  all passed, including the variant's own checks (no PKCS#11 modules or helper, no CryptoPro tool run, stamp library
  and signing keys in the shared folder, 9 strings × 20 languages).
- Same `--selftest` of the release build without the flag: all passed, no variant checks.
- The DMG build compiles no variant code, but its executables are not byte-identical to the previous commit: the
  empty `AppStoreEdition.swift` object adds 688 bytes, and the inserted `#if` lines shift source line numbers that
  Swift embeds for runtime traps (plus the resulting LC_UUID and signature). P11Bridge42 is byte-identical.
