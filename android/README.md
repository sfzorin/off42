# OFF42 for Android

A native Android app for tablets and phones (ARCHITECTURE.md, decision D10): Kotlin, Jetpack Compose and Material 3
over the shared Rust engine, called through the UniFFI crate [`rust/crates/off42-mobile`](../rust/crates/off42-mobile).
Application id **`cc.off42.office`**, name **OFF42**, minimum Android 8.0 (API 26), target API 36.

It covers what the web app covers, with the same engine calls. It is offline: the app requests no permissions (no
`INTERNET`) and reads or writes files only through the system file picker, "Open with" and sharing.

## Screens

Six sections. Large screens (expanded width) show a navigation rail and the opened files next to the selected file;
medium widths show the rail with list → file navigation; phones show a bottom navigation bar.

| Section | What it does |
| --- | --- |
| Documents | Opens DOCX, ODT, RTF, Markdown, HTML and TXT. Preview of the engine's HTML in a WebView with JavaScript off, no file/content access and every network or subresource load blocked; word, character and paragraph counts; **Save as** DOCX/ODT/RTF/MD/HTML/TXT. When a conversion would drop opaque Word/OpenDocument package parts, the app asks first. |
| Spreadsheets | Opens XLSX, ODS, CSV and XLS (read-only). Virtualised grid (rows in a `LazyColumn`, sticky column header, row numbers, shared horizontal scroll, numbers right-aligned), sheet tabs, first 1000 rows × 100 columns. Save as XLSX/ODS/CSV; "Sheet values as CSV" (the only export for XLS). |
| Presentations | Opens PPTX and ODP as outline cards (title, bullets, tables, picture placeholders, notes, hidden slides) in an adaptive grid. Save as PPTX/ODP. |
| PDF | Pages rendered on the device by Android's `PdfRenderer` at the shown width, plus the engine's page count, metadata, bookmarks, attachments and form fields. Save a copy or share. Password-protected PDFs show a notice. |
| Labels & codes | QR, Data Matrix, Code 128 and Aztec with a live preview; save PNG or SVG, share. A4 label sheets from `text \| code \| copies` lines on any of the built-in stocks (searchable) or a custom size, with a preview of the first page; save or share the PDF. The 97 product marks with search, category filter and a detail view (purpose, warnings, licence notes); save SVG or PNG at any width. |
| Signatures & stamps | Six signature variants per name, form, pen and ink, each with "New impression", save and share as transparent PNG. Stamps from the built-in templates with editable fields (dates default to today), ink, live preview, new impression, save or share at 2× scale. |

Files are opened with the section's **Open file** button (`ACTION_OPEN_DOCUMENT`), from other apps ("Open with",
`ACTION_VIEW`) or by sharing to OFF42 (`ACTION_SEND`). Results are saved with the system save dialog
(`ACTION_CREATE_DOCUMENT`) or shared through a `FileProvider` limited to the app's `cache/shared` folder. Engine calls
run on `Dispatchers.Default`; open files and pending saves live in a `ViewModel`, so rotation keeps them.

The theme follows the system light/dark setting (brand colours from `website/public/assets/favicon.svg`); the
adaptive launcher icon is the site's "42" mark, with a monochrome layer for themed icons.

### Languages

The UI is in the 20 languages of the site and the web app (Arabic right-to-left), with Android 13's per-app language
setting (`res/xml/locales_config.xml`). `res/values*/strings.xml` are generated by
[`scripts/generate-strings.py`](scripts/generate-strings.py) from the web app's `web/src/locales/*.json` and the
Android-only strings in [`scripts/strings-android.json`](scripts/strings-android.json); rerun it after changing either.
As in the web app, messages from the engine are in English, stamp template titles exist in English, Russian and
Turkish only, and their field labels and categories are English.

### Limits

What the engine does not do on any platform yet is missing here too: editing, exporting documents/sheets/slides to
PDF, slide pictures and layouts, PDF annotation and OCR. A drawn signature is an image, not a certificate-based
digital signature. Large files are read into memory.

## Build

Requirements: JDK 17, the Android SDK (`ANDROID_HOME`; Gradle installs the missing platform), the Rust toolchain with
`rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android`, `cargo install cargo-ndk`, and
an NDK (`ANDROID_NDK_HOME`).

```sh
android/scripts/build-rust.sh            # engine .so for arm64-v8a, armeabi-v7a, x86_64 + Kotlin bindings + host library
cd android
./gradlew assembleDebug                  # app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest lint         # JVM tests call the real engine through JNA (host library)
./gradlew bundleRelease                  # app/build/outputs/bundle/release/app-release.aab (minified)
```

`build-rust.sh` writes `app/rust-out/` (ignored by git): `jniLibs/<abi>/liboff42_mobile.so` (profile
`mobile-release`: LTO, stripped), `kotlin/cc/off42/mobile/off42_mobile.kt` (generated by UniFFI from the built library)
and `host/` (the library for the machine that builds, for unit tests). Gradle stops with a hint when the bindings are
missing. `OFF42_SKIP_ANDROID=1 android/scripts/build-rust.sh` builds only the bindings and host library: enough to
compile, lint and unit-test, but the APK then has no engine library and cannot run.

## Tests

- `cargo test -p off42-mobile`: the bindings against the cores (formats, typed errors, generators).
- `./gradlew testDebugUnitTest`: Kotlin engine layer on the JVM (grid geometry, language codes, MIME mapping, file
  loading, typed exceptions, deterministic generators).
- `./gradlew connectedDebugAndroidTest` (needs a device or emulator; CI only for this project):
  [`AppTest`](app/src/androidTest/java/cc/off42/office/AppTest.kt) opens every fixture format
  ([`app/src/androidTest/assets/fixtures`](app/src/androidTest/assets/fixtures)) in its viewer, opens a file through an
  `ACTION_VIEW` content URI, converts MD → DOCX, DOCX → ODT (through the package-parts question), CSV → ODS and
  PPTX → ODP through the real Save button with the system save dialog answered by an Espresso-Intents stub and checks
  the written files with the engine, generates codes, a label sheet, marks, signatures and a stamp, rotates the
  device and switches the system to dark mode with a file open. It writes the Play screenshots to test storage.

The fixtures were made by the engine from `web/test/fixtures` (`OFF42_FIXTURES=<dir> cargo test -p off42-mobile --
--ignored fixtures`), except `sample.xls`, which LibreOffice 25 wrote from `sample.xlsx`
(`soffice --headless --convert-to xls`) because the engine cannot write XLS.

## CI

[`.github/workflows/android.yml`](../.github/workflows/android.yml) on `ubuntu-latest`:

1. **engine**: `cargo test -p off42-mobile`, cargo-ndk build of the three ABIs with the runner's NDK, Kotlin bindings.
2. **build**: `./gradlew assembleDebug bundleRelease testDebugUnitTest lint`, a check that the release manifest requests
   no permissions, and the debug APK and release AAB as artifacts (sizes in the job summary).
3. **emulator** (tablet `pixel_tablet` and phone `pixel_6`, API 34, x86_64): the instrumented tests; screenshots and
   reports as artifacts.
4. **apple** (`macos-latest`): the same bindings for iPadOS/iOS (see the crate's README).

## Release

The release bundle is minified with R8 (`proguard-rules.pro` keeps JNA and the bindings). CI signs it only when the
repository has the secrets `ANDROID_KEYSTORE_BASE64` (base64 of the keystore), `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS` and `ANDROID_KEY_PASSWORD`; locally, set `ANDROID_KEYSTORE_FILE` and the same variables. Without
them the AAB is unsigned. `OFF42_VERSION_CODE` sets the version code (default 1). Store listing, data-safety answers
and what is still needed for Play are in [play/README.md](play/README.md).
